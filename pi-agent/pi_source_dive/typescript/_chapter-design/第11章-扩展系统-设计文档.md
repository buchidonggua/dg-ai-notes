# 章节设计文档：第11章 扩展系统 —— 不改源码给 Agent 加能力

> **源码基准**：2026-10-12 本地 `pi-main` 快照，核心包 `v0.84.3`。
> **目标读者**：读过前 10 章，理解 Agent Loop、工具、消息、事件与会话，但没有插件系统设计经验的开发者。
> **目标**：能写最小扩展，沿注册、绑定、事件消费追踪行为变化，并区分接口边界与安全隔离。
> **状态**：本设计已按最终第11章正文回填；TS 与 Python 使用同一份设计。

---

## 1. 本章一句话

扩展通过宿主已经提供的工作流节点介入行为；理解扩展，需要追踪事件的生产者、返回协议和消费者，而不只是记住事件名。

## 2. 叙事线索

从“团队希望阻止一类 bash 命令，但不想每次升级都修改核心”出发：

1. 写一个扩展工厂，用 `pi.on("tool_call", handler)` 注册策略。
2. 模型产生工具调用，Agent Core 预处理并验证参数。
3. coding-agent 的前置钩子调用 runner，构造并分发扩展事件。
4. 处理器返回 block，Agent Loop 跳过执行并生成错误工具结果。
5. 回看扩展怎样被发现、加载，以及运行时动作怎样绑定。
6. 用会话切换取消展示另一份返回协议，再讨论错误、状态与权限边界。

### 2.5 概念空白清单

| 概念 | 引入方式 | 正文位置 |
|---|---|---|
| 工作流事件协议 | 事件名、输入、返回值与消费点四件事共同决定行为 | §二、§三 |
| 工厂函数 | 先声明处理器和工具，运行时再处理事件 | §三、§四 |
| Jiti | 运行时加载 TS 模块；文件变化后通过重新加载生效 | §四 |
| throwing stubs | 注册期部分动作尚未可用，调用会报错 | §四 |
| bindCore | 将共享 runtime actions 绑定到宿主实现 | §四 |
| API 门面 | 限定可见接口和调用时机；不是进程权限隔离 | §七 |
| emitter 专属异常策略 | 对照通用通知、变换、tool_call 和会话取消路径 | §六 |

## 3. 知识点分层

**主线**：tool_call 的注册到消费闭环；加载与运行时绑定；不同事件的返回和异常语义。

**支线**：工具包装器、扩展工具注册、会话切换取消、项目 trust 与扩展权限。

**边界**：不罗列固定事件总数；不将所有处理器视为同一个通用事件总线；不把正则命令匹配或 API 门面称为安全沙箱。

### 3.5 方法论提炼

| 方法 | 源码落点 | 迁移方式 |
|---|---|---|
| 稳定工作流节点 | `ExtensionAPI.on`、各 runner emitter | 同时定义输入、返回协议、消费者和异常策略 |
| 注册与执行分期 | loader runtime、runner `bindCore` | 注册期只声明能力，依赖当前状态的动作放到运行时 |
| 工具接口适配 | `wrapToolDefinition` | 在产品边界注入上下文，让 Agent Core 保持独立 |
| 可验证的闭环 | `tool_call`、`session_before_switch` | 断言实际执行与状态结果，避免仅验证 handler 返回值 |

## 4. 认知旅程

**第一段：从需求到结果。** 展示命令拦截扩展，再逐步追到参数校验、`emitToolCall`、block 和模型可见的 ToolResultMessage。

**第二段：从可写到可运行。** 解释 Jiti、扩展工厂、注册期 stub、ResourceLoader 与 AgentSession 的绑定顺序；用工具示例说明第五个上下文参数如何注入。

**第三段：从单个示例到边界。** 用 `session_before_switch` 取消与 tool_call 阻止做对照，然后分别处理通知、变换、工具异常和取消语义。

### 4.5 链路闭环清单

| 链路 | 触发端 | 中转 | 消费端和结果 |
|---|---|---|---|
| 命令拦截 | 模型产生 bash ToolCall | Agent Core 准备 → session 前置钩子 → runner | handler 返回 block；Loop 跳过 execute，产生工具错误结果 |
| 工具注册 | 工厂调用 registerTool | loader 保存定义 → session 组装 → wrapper | Agent Core 调用四参数 execute；wrapper 注入第五个 ctx |
| 会话切换取消 | 宿主准备切换会话 | session_before_switch → runner | handler 返回 cancel；宿主停止该切换操作 |

## 5. 数据展示清单

| 数据 | 展示目的 |
|---|---|
| bash 的 command 与 toolCallId | 将一个调用从事件入口关联到最终结果 |
| `{ block: true, reason }` | 解释拦截返回值怎样被消费者落实 |
| 自定义工具定义与第五个 ctx | 解释产品接口与内核接口的适配 |
| `{ cancel: true }` | 说明会话取消与工具阻止使用不同协议 |
| 扩展注册、绑定与消费 SVG | 将 loader、runtime、runner、session、Loop 连成完整链路 |

## 6. 转折点设计

1. Pi 不知道团队策略，为什么扩展仍能改变行为？用已有工作流节点回答。
2. 工厂加载时为什么不能随意操作当前 Agent？用注册期 stub 与后续绑定回答。
3. handler 抛错后是否都能继续？逐个 emitter 追踪，避免统一容错承诺。
4. 提供受限 API 是否就安全？区分接口组织与宿主进程权限。

## 7. 与前文的衔接

第5章提供工具管道和包装器背景，第7章区分内核事件与扩展事件，第10章提供会话切换背景。

第12章承接“怎样证明扩展真的阻止执行”：用不调用真实模型的测试设施，检查事件、执行次数、队列和最终状态。
